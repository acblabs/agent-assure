# agent-assure v0.6.1

v0.6.1 expands the development-RFC mutation surface from three individual
operators to a closed seven-operator catalog and adds deterministic campaign
execution over one immutable fixture RunSet.

Highlights:

- adds four deterministic operators for evidence source-identity skew,
  synthetic sensitive-summary injection, duplicate observation replay, and an
  incomplete synthetic budget-stop state;
- publishes the exact `core/v1` seven-operator mapping across material-evidence,
  human-review, tool-boundary, provenance, privacy, stream-replay, and
  RunSet-completion invariant families;
- gives every operator one normative target control and reason code, plus an
  explicit prohibited runtime-failure substitute that cannot count as
  detection;
- adds self-digested `AssuranceMutationCatalog/v1` and
  `AssuranceMutationCampaign/v1` artifacts under the v0.6.1 schema surface;
- binds the canonical catalog digest to lexicographic ordering semantics, full
  operator descriptors, implementation and expected-detector identities,
  provenance, independence, threat-source references, and limitations;
- adds `controls mutate --catalog core/v1` with repeatable operator,
  invariant-family, and threat-ID filters, a stable seed, and mutually exclusive
  full-report and fail-fast modes;
- runs every selected operator independently against the same immutable source;
  mutation composition and chaining remain forbidden;
- records canonical selected, executed, and pending operator order,
  applicability, expected and observed detector evidence, prohibited
  substitutes, exact nested result paths, semantic states, bounded diagnostics,
  and campaign limitations;
- isolates operator failures in full-report mode and defines deterministic
  worst-state exit precedence for campaign automation;
- keeps current v0.6.1 runtime invariants applicable when projecting frozen
  v0.6.0 artifacts, while preserving the v0.6.0 schema snapshot for replay;
  and
- documents a contribution route through reviewed source and synthetic-fixture
  pull requests without dynamic executable plugin loading.

## Upgrade behavior

Ordinary RunSet evaluation now always compares `source_id` for paired
`EvidenceRef` and `EvidenceItem` records that share a `ref_id`. A mismatch or
multiple source identities emits the blocker
`EVIDENCE_PROVENANCE_MISMATCH` finding from
`evidence_provenance_identity`; this is not a mutation-only check. Existing
RunSets with inconsistent paired source identities can therefore newly block
after upgrading. The control establishes internal reference/item identity
consistency only. It does not authenticate the external source or its content.

Incomplete RunSets now emit the dedicated `RUNSET_INCOMPLETE` reason from
`runset_completion_required`. `RUNTIME_FAILED` remains reserved for actual run
execution failures; for `mark-incomplete-budget-stop`, it is only the explicit
prohibited substitute and cannot count as detection.

The incomplete-RunSet finding reports only the number of declared stop reasons;
it does not copy caller-supplied stop-reason text into findings, console output,
or Markdown reports.

Limitations:

- The catalog is a finite, authored set of first-party post-control challenges.
  It is not independent red-team or third-party validation.
- Campaign output is catalog- and subject-relative. It is not a safety score,
  mutation kill rate, statistical confidence interval, or universal-coverage
  claim.
- Operators do not compose, generate new attacks, execute synthetic tool names,
  authenticate external evidence sources, or simulate provider billing.
- A caught result means only that the bound normative detector responded to
  that exact transformation under the declared configuration. Current built-ins
  permit non-prohibited newly observed secondary findings, preserve them in the
  result, and do not claim exclusive detector isolation.
- This implementation note does not claim that release provenance has been
  stamped, that a distribution has been published, or that an external party
  has validated the catalog.
