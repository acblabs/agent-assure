# agent-assure v0.6.3

v0.6.3 adds an authenticated, self-digested assurance evidence graph to the
release packet and strengthens the surrounding evaluator, verifier, process,
network, and file-integrity boundaries.

Highlights:

- adds `AssuranceEvidenceGraph/v1`, a closed four-node/five-edge projection of
  evaluation, comparison, mutation, control-efficacy, gate, and limitation
  evidence with RFC 8785 identities and a recomputed semantic graph digest;
- binds first-party packets to both the graph's semantic digest and its exact
  file digest while keeping graph presence optional for compatible third-party
  v0.6 packet producers;
- adds an optional canonical `runset_digest` to `EvaluationSummary`; first-party
  evaluators emit it so control-efficacy and gate evidence join the primary
  run-set subject only when the source identity is authenticated;
- makes `packet graph` reject output paths that alias packet-bound artifacts,
  while preserving idempotent in-place emission of the packet's exact bound
  graph;
- versions core replay roles by the replay schema: releases through v0.6.2 keep
  the historical four-role requirement and v0.6.3 additionally requires the
  assurance evidence graph;
- signs and verifies the privacy-filtered evaluation summary, comparison
  summary, evidence graph, packet, manifest, replay record, SBOM, distributions,
  and release notes as one coherent set; cross-file packet bindings are checked
  after per-blob signature verification;
- enforces provider execution allowlists independently from review routing and
  tightens waiver, required-policy, stream, authored-YAML, suite, run-set, and
  evidence-identity invariants;
- pins OpenAI-compatible HTTPS connections to freshly screened DNS answers
  while retaining hostname-based TLS verification;
- represents observed zero-denominator live rates as undefined and fail-closed
  instead of fabricating numeric zero estimates;
- confines rooted reads through descriptor-based checks and strengthens
  external-script lifecycle containment on Linux and Windows; and
- requires current packets to bind their nested evaluation and optional
  comparison summaries to exact source bytes during standalone and full CI
  verification.

## Upgrade behavior

Current package and persisted-schema metadata advance to v0.6.3. Existing
released schema snapshots remain frozen and replayable. The evidence graph and
`EvaluationSummary.runset_digest` belong to the v0.6.3 writer surface; no
historical schema file is rewritten.

First-party evaluation output now includes `runset_digest`. The field remains
optional at the model boundary for legacy and third-party summaries that cannot
authenticate a source RunSet. When the digest is absent, digest-scoped mutation
or control-efficacy evidence remains on an explicit separate subject rather
than receiving an invented join.

The verified GitHub release evidence set expands to retain and sign the packet-
bound evaluation and comparison summary JSON files. Consumers should verify the
complete fixed asset set and its signature bundles, then run the documented
packet binding check; independently valid assets from separate workflow reruns
are not interchangeable merely because their stable replay projections match.

`packet graph --out` now fails before writing when the destination is a bound
evaluation summary, comparison summary, release manifest, packet artifact, or
other protected role. Re-emitting the packet's bound graph to its existing graph
path succeeds only when the projected semantic digest matches the packet.

Current live-statistics output no longer reports a numerical rate or interval
for an observed zero denominator. Callers must handle the explicit undefined
state. Configured external scripts receive stronger process containment, but
the mechanism remains lifecycle containment for trusted configured code rather
than a hostile-code sandbox.

## Verification boundary

The graph is descriptive evidence transport. It does not recalculate or
override the typed evaluation, comparison, or control-efficacy gate decision.
Signature verification establishes signer and blob integrity; the additional
packet binding check establishes that the signed packet, summaries, graph, and
manifest form one exact evidence set.

Limitations:

- A graph whose evaluation summary lacks an authenticated run-set digest may
  contain multiple weakly disconnected subject components. Consumers must
  inspect all typed nodes rather than treating `primary_subject_node_id` as a
  graph-wide completeness root.
- Canonical graph validation establishes deterministic structure and binding,
  not that the underlying evidence is empirically complete, externally
  validated, safe, representative of production behavior, or sufficient to
  satisfy any legal or policy requirement.
- The built-in mutation and control-efficacy fixtures remain deterministic
  first-party challenge evidence. They are not an external red-team result or a
  statistical estimate of system safety.
- DNS screening and process containment reduce specific local execution risks;
  they do not provide a general network policy engine or adversarial same-user
  sandbox.
- This implementation note does not claim that release provenance has been
  stamped, that a distribution has been published, or that an external party
  has validated the evidence graph.
